# The _Answers Quality_ menu

The _Answers Quality_ menu helps business teams measure and improve the quality of the bot answers,
in particular the answers generated by the [RAG](rag.md). It provides two tools:

* [_Evaluations_](#evaluations): humans review and grade a sample of real (or test) conversations.
* [_Datasets_](#datasets): a fixed list of questions is replayed against the bot, so that runs can be compared
  after a change of settings, prompt or documents.

> To access this menu, you need the **_botUser_** role
> (more details on roles in [security](../operate/security.md#roles)).

## Evaluations

An _evaluation sample_ is a set of dialogues whose bot answers are reviewed one by one.

### Creating a sample

![New evaluation sample](../img/studio/evaluation-new-sample.png "New evaluation sample")

Click on **NEW SAMPLE** and fill in:

* the _Sample name_ and an optional _Sample description_,
* the _Number of dialogues_ to randomly select,
* the period covered, with a _Start date_ and an _End date_: only dialogues created during this period are selected,
* _Allow test dialogues_: whether dialogues created from _Tock Studio_ tests can be selected.

A sample can also be [created from a dataset run](#creating-an-evaluation-sample-from-a-run).

The list of samples shows, for each sample, its type (random or generated from a dataset run), its state
(_In Progress_ or _Validated_), its positive score, its number of dialogues and answers, and who created and validated it.

### Evaluating the answers

Open a sample to review its dialogues. For each bot answer:

* evaluate it positively (thumb up),
* or evaluate it negatively (thumb down) and choose a reason:
    * Question not/misunderstood
    * Inaccurate answer
    * Incomplete answer
    * Incomplete sources / documents
    * Obsolete sources / documents
    * Business lexicon problem
    * Wrong answer format
    * Hallucination
    * Other

The progress bar shows the number of evaluated answers, and the positive / negative evaluations.
The sample details give the period covered, the number of requested and actual dialogues, the total number of
dialogues recorded for the bot during the period, and the resulting coverage rate.

### Validating a sample

Once all the answers are evaluated, click on **Validate** and add an optional comment.
A validated sample can no longer be modified. It can be exported as a PDF report with **Export**.

> Dialogues are subject to the data retention policy of the platform.
> If some dialogues of a sample have been purged, a warning is displayed and the sample can no longer be validated.

## Datasets

A _dataset_ is a named list of questions, each with an optional _ground truth_ (the expected answer).
Running a dataset sends every question to the bot and records the answers, so that two runs can be compared
question by question: typically before and after a change of the RAG settings, of the prompt or of the indexed documents.

### Creating a dataset

![Datasets](../img/studio/datasets-list.png "Datasets")

Click on **NEW DATASET**, then enter a name, an optional description and the questions,
with an optional ground truth for each of them.

A dataset can also be imported (button _Import a dataset_):

* from a JSON file containing a `name`, a `description` and an array of `questions`,
  each with a `question` and a `groundTruth` field,
* or from a CSV file with a `question` column and an optional `groundTruth` column:
  download the _CSV template_ from the import dialog to get the expected columns.
  The name and description are then entered in the dialog.

![Edit dataset](../img/studio/dataset-edit.png "Edit dataset")

From the edition screen, **EXPORT DATASET** exports the full dataset as JSON, or its questions only as CSV.

> Run results are matched by question. Rephrasing a question slightly is fine, but changing its meaning
> makes runs compare different things: in that case, delete the question and add a new one.

### Running a dataset

Click on _Run dataset_. Each question is sent to the bot with the [test connector](../studio/test.md), as if typed in the
_Test_ menu, with the debug mode and the source contents enabled. Questions are processed one by one, in the background:
the list shows the progress of the active run, which can be cancelled.

Running a dataset requires a test configuration for the bot. Only one run can be active for a dataset,
and a dataset cannot be edited or deleted while a run is active.

For each run, the list of runs shows its dates, duration and state, and counts the questions:

* _Completed_ and _Failed_ (execution failures or technical errors),
* _Intent_: answered by intent detection,
* _Found in context_: answered by the RAG with relevant documents,
* _Not found in context_: handled by the RAG without relevant documents.

A run that ends with some failed questions is still _completed_: failed questions are reported in the run statistics.

### Comparing runs

Open a run to display its answers. The screen compares a _Run A_ with a _Run B_ (by default, the latest run),
question by question: answer text, answer type (RAG or intent) and sources. Sources that were added, modified or removed
between the two runs are highlighted.

The _Show only diffs_ filters display only the questions whose status, sources, answer type or wording changed.

The _settings_ and _prompts_ links show the RAG settings and prompts used by each run, and compare them between the two runs.

### Creating an evaluation sample from a run

From the list of runs, _Create an evaluation sample based on the results of this run_ creates an
[evaluation sample](#evaluations) containing the answers of the run, so that they can be graded by humans.

## Configuration

The following properties of the _Tock Studio_ backend (`tock/bot_admin`) configure datasets:

| Environment variable                       | Default | Description                                                  |
|--------------------------------------------|---------|--------------------------------------------------------------|
| `tock_datasets_max_questions`              | `200`   | Maximum number of questions in a dataset                     |
| `tock_dataset_run_worker_poll_interval_ms` | `2000`  | Interval between two checks for new runs to process (ms)     |
| `tock_dataset_run_worker_max_retries`      | `0`     | Number of retries of a question after a technical error      |
